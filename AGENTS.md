# AGENTS.md

## Назначение

Этот файл задаёт рабочие правила для ИИ-агентов (Codex, Antigravity) в репозитории `uhabits-plus`. Актуальные сведения о продукте находятся в `docs/codex-project-context.md`, архитектурная карта кода — в `docs/architecture-uhabits.md`.

## Перед началом работы

1. Прочитать `docs/codex-project-context.md`. Для работы над UHabit Next сначала прочитать канонический `C:/Users/Pavel/source/repos/uhabits-plus/docs/UHABIT_NEXT_HANDOFF.md`: текущую область, принятые решения и Active work; сверить состояние с Git и зарегистрировать узкую область по его протоколу.
2. Для задач по коду, UI, данным, сборке или архитектуре прочитать релевантные разделы `docs/architecture-uhabits.md`.
3. Проверить рабочее дерево (`git status`) и не затрагивать чужие незакоммиченные изменения.
4. Перед изменениями кратко назвать план и предполагаемые файлы.

Для расследований производительности сначала читать [каноническое расследование](docs/performance/HABIT_INTERACTION_INVESTIGATION.md): выбрать один ограниченный вопрос и критерии проверки; в конце обновить доказательства, результаты и следующий шаг. Не повторять аудит без нового вопроса или доказательств.

## Принципы изменений

- Решать поставленную задачу, не добавляя несвязанный рефакторинг.
- Сначала проверять существующую реализацию и только затем менять её.
- Не считать документацию или воспоминания источником истины, если их можно сверить с кодом.
- Изменения моделей, схемы БД, синхронизации, формул статистики и build-конфигурации допустимы, когда этого требует задача; в таком случае явно описывать совместимость, миграцию и проверки.
- Сохранять форматы данных и поведение вне области задачи либо отдельно объяснять намеренное изменение.

## Актуальность основных документов

Обновлять документацию в той же задаче, если изменение затрагивает факты в основных документах:
- `docs/codex-project-context.md` — состав продукта, ключевые экраны, стек, инварианты данных;
- `docs/architecture-uhabits.md` — модули, навигация, ключевые классы, потоки, схема БД, миграции, timer/sync architecture.

Локальные исправления, не меняющие описанные факты, не требуют правки документации.

## Формат коммитов

- Заголовок строго в формате `<Scope>: <краткое описание на английском в present/imperative tense>`. Без точки на конце.
- Однострочные коммиты без описания запрещены.
- Обязательно подробное тело коммита, отделённое пустой строкой, в виде маркированного списка (`- ...`).
- Каждый пункт должен содержать конкретное техническое описание: что изменено, архитектурные решения, затронутые UI/компоненты/модели, исправленные граничные случаи и совместимость.
- Пример:
  ```
  Settings: introduce adaptive sectioned navigation and polished preference UI

  - Replace the legacy preferences screen with card-based Settings home and detail sections.
  - Add adaptive row sizing, consistent typography, stable accessories, and Light, Dark, and AMOLED styling.
  - Organize appearance, habits, notifications, Pomodoro, statistics, backup, sync, help, and developer preferences into focused sections.
  ```

## Работа с репозиторием

- Для текстового поиска, ресурсов, Gradle и XML использовать `rg` / `rg --files`; не сканировать репозиторий целиком без необходимости.
- `codebase-memory-mcp` использовать для архитектурных связей, графа вызовов и зависимостей символов; при неготовности индекса сразу переходить на `rg` или `ast-grep`, не блокируя задачу.
- Предпочитать точечные, сфокусированные команды и избегать неконтролируемого вывода больших объёмов сырого текста.
- Перед завершением проверить `git diff --stat`, `git diff --name-only` и релевантный diff.
- Markdown-файлы по умолчанию локальны и игнорируются правилом `*.md`. Исключения в `.gitignore` для `docs/UHABIT_NEXT_HANDOFF.md`, `docs/UHabit_Next_Spec.md` и `docs/uhabit-next-foundation-plan.md` сохраняют эти канонические документы в Git. Остальные Markdown не добавлять в Git без прямого запроса пользователя.
- Не удалять и не перезаписывать незнакомые untracked-файлы.

## Проверка

Выбирать минимальную проверку по типу изменения:
- Android UI/resources: `.\gradlew.bat :uhabits-android:assembleDebug --console=plain --quiet`
- Android Kotlin: `.\gradlew.bat :uhabits-android:compileDebugKotlin --console=plain --quiet`
- Core logic: точечный `:uhabits-core:jvmTest --tests "<TestClass>"`

Не запускать полный набор или instrumentation tests без явной причины. Для UI-задач успешная компиляция не заменяет визуальную проверку на устройстве или эмуляторе.

## Отчёт

Кратко описать изменения, выполненные проверки, известные риски и реальные препятствия. Не объявлять задачу готовой, если обязательная для неё проверка не состоялась.
